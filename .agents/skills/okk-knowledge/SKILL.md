# Знания по проекту ОККМ (OKK UI)

Данный скилл содержит ключевые технические правила, архитектуру и отправную точку из `CLAUDE OKK.md` для проекта ОККМ.

## 1. Суть проекта
- B2B SaaS «ОККМ» — контроль качества клиентских коммуникаций.
- Бейджи AB-400 пишут `.wav` -> S3 -> FastAPI бэкенд -> Мультимодальный Gemini LLM (транскрипт + 6 триггеров чек-листа + оценка 0..10 + сводка в один запрос) -> Postgres -> Админка.
- Ключевые тенанты: `azs` (АЗС) и `pharmacy` (Аптеки).

## 2. Разделение Фронтенда
- `demo.html` (или `landing/demo.html`) — мок-дизайн дашборда (Glassmorphism, 6 триггеров АЗС, графики, интерактивные карточки).
- `app.html` (или `app/index.html`) — единственный РАБОЧИЙ фронтенд на Vanilla JS, вызывающий `/api/*`.
- **Наша задача:** Портировать визуальный Glassmorphism-дизайн из `demo.html` в `app.html`, сохранив интеграцию с реальным REST API.

## 3. Требования к триггерам АЗС (6 ключевых критериев)
1. **Приветствие:** Вежливое приветствие («Добрый день/утро/вечер!», «Добро пожаловать!»). Кассир НЕ обязан представляться по имени. Запрещено сухое «Здравствуйте» и автоштраф за «Здрасьте/Здрасти».
2. **Продажа кофе:** Утвердительное предложение фирменного кофе в дорогу без отрицательной частицы «НЕ».
3. **Выпечка и кросс-сейл:** Конкретное предложение («хот-дог или самса»), полный запрет на ленивое «Что-нибудь еще?».
4. **Верификация заказа:** Полное озвучивание перед расчетом (колонка, топливо, объем/сумма, доп. товары, способ оплаты).
5. **Выдача чека молча:** Чек выдается по умолчанию в руки, запрет на вопросы «Вам чек нужен?».
6. **Стандарт прощания:** Вежливое прощание («Счастливого пути!», «Ждем вас снова!») без сухого «До свидания» или молчания.

## 4. Правила работы и Git Flow
- Работа строго локально в отдельной ветке (`feature/dashboard-redesign`).
- Никаких `git commit` и `git push` без явного текстового разрешения пользователя.
- Не производить записи на прод без одобрения.
