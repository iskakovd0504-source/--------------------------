# ТЗ: SEO + GEO оптимизация сайта aiprotocol.kz

**Заказчик:** ТОО «Aiprotocol.kz» (продукт ОККМ / AiProtocol)
**Дата:** 20.08.2026
**Приоритет:** SEO и GEO — в равной степени
**Отрасли контента:** все отрасли сайта равномерно (АЗС, аптеки, ритейл, медицина, услуги и авто)
**Архитектура:** разрешено менять (создавать новые URL/страницы)

---

## 0. Контекст и текущее состояние (аудит на момент ТЗ)

Сайт aiprotocol.kz сейчас фактически **одностраничник**: разделы «Как это работает», «Метрики», «Отрасли», «Тарифы» реализованы как якоря (`#industries`, `#pricing` и т.д.) внутри `index.html`, а не отдельные индексируемые страницы. Это ограничивает попадание в поиск по узким коммерческим запросам («аудиобейджи для аптек», «контроль качества АЗС» и т.п.).

Что уже есть и что можно переиспользовать:
- Заполнены `title`, `meta description`, `og:*` — база в порядке, но нужно расширять под новые страницы
- Блог существует (`/blog/`), но всего 2 статьи — контента критически мало
- Готовый блок FAQ на главной — прямая база под `FAQPage` разметку
- Готовые отзывы клиентов (Qazaq Petrol, Sunkar Pharm) — база под `Review`/`AggregateRating`
- Есть EN-версия (`/en/`)
- **Найдена несостыковка контактов**: на главной телефон `+7 777 555 67 89`, в футере блога — `+7 771 234 5667`. Требует исправления до начала локального SEO (NAP-консистентность критична для 2GIS/Google Business/Яндекс.Бизнес)

## 1. Архитектура сайта (приоритет: высокий)

### 1.1 Новые индексируемые страницы вместо якорей

Разбить текущие секции главной страницы на отдельные URL, сохранив главную как конверсионный хаб со ссылками на них:

| Текущий якорь | Новый URL | Заметки |
|---|---|---|
| `#industries` (АЗС) | `/otrasli/azs/` | есть кейс Qazaq Petrol — использовать как основу |
| `#industries` (Аптеки) | `/otrasli/apteki/` | есть кейс Sunkar Pharm — использовать как основу |
| `#industries` (Ритейл) | `/otrasli/ritejl/` | |
| `#industries` (Медицина) | `/otrasli/medicina/` | |
| `#industries` (Услуги и авто) | `/otrasli/uslugi-i-avto/` | |
| `#pricing` | `/tarify/` | сохранить калькулятор, добавить расширенный текстовый контент вокруг тарифов |
| `#how-it-works` | `/kak-eto-rabotaet/` | |
| — | `/keysy/` | хаб-страница со всеми кейсами, каждый кейс — отдельная подстраница `/keysy/qazaq-petrol/`, `/keysy/sunkar-pharm/` |

Все отраслевые страницы дублируются под EN: `/en/industries/gas-stations/` и т.д. — с `hreflang` между ru/en версиями.

### 1.2 Структура отраслевой страницы (шаблон)

Каждая `/otrasli/*` страница должна включать:
1. H1 с отраслевым ключевым запросом («Речевая аналитика для АЗС в Казахстане»)
2. Проблематика отрасли (адаптированный текст с главной)
3. Как решение работает конкретно для этой отрасли (метрики, релевантные именно ей)
4. Кейс/отзыв клиента из этой отрасли (если есть)
5. Блок FAQ, специфичный для отрасли (с разметкой `FAQPage`)
6. CTA на демо/тест-драйв

### 1.3 Технические требования к новой структуре
- Canonical-теги на всех страницах
- `hreflang="ru-KZ"` / `hreflang="en"` между парами страниц
- Внутренняя перелинковка: главная → отраслевые страницы → кейсы → блог, и обратно
- Хлебные крошки (breadcrumbs) с разметкой `BreadcrumbList`

## 2. Технический SEO

- [ ] Проверить/создать `robots.txt` в корне домена, указать директиву `Sitemap:`
- [ ] Создать `sitemap.xml` (и `sitemap_index.xml`, если структура вырастет), включить все новые страницы, `lastmod`, исключить служебные/некэнонические URL
- [ ] **Исправить NAP-несостыковку**: единый номер телефона, единое написание адреса/юрлица во всех местах сайта (шапка, футер, блог, EN-версия)
- [ ] Проверить и настроить корректные HTTP-статусы (200 для всех страниц из sitemap, 301 для редиректов при смене URL)
- [ ] Аудит скорости загрузки / Core Web Vitals (LCP, CLS, INP), оптимизация изображений (сейчас используются `.jpg/.png` дашбордов — перевести в `webp`, добавить `loading="lazy"`)
- [ ] Проверить мобильную версию всех новых страниц
- [ ] Настроить/проверить Google Search Console и Яндекс.Вебмастер, отправить sitemap

## 3. Структурированные данные (schema.org)

Внедрить JSON-LD разметку:

- [ ] `Organization` — на всех страницах (name, logo, url, contactPoint, sameAs → WhatsApp/Telegram/Instagram)
- [ ] `LocalBusiness` — если есть физический адрес/офис (уточнить у заказчика для локального SEO)
- [ ] `Product` / `Service` — для ОККМ как продукта, с описанием и ссылкой на тарифы
- [ ] `FAQPage` — на главной и на каждой отраслевой странице (использовать существующие вопросы + новые отраслевые)
- [ ] `Review` + `AggregateRating` — на кейсах и главной (использовать существующие отзывы Qazaq Petrol, Sunkar Pharm)
- [ ] `BreadcrumbList` — на всех внутренних страницах
- [ ] `Article` — на всех постах блога (author, datePublished, image)

Каждый блок разметки проверить через Google Rich Results Test перед публикацией.

## 4. Контент-план (SEO + GEO)

### 4.1 Блог — расширение
Сейчас 2 статьи. Нужен контент-план на **минимум 15-20 статей**, равномерно по отраслям и по общим темам:
- По каждой отрасли (АЗС, аптеки, ритейл, медицина, услуги/авто): минимум 2-3 статьи с реальными цифрами, кейсами, сравнениями «до/после»
- Общие темы: «речевая аналитика vs тайный покупатель», «как считать ROI от контроля качества», «требования закона РК к записи разговоров сотрудников» (юридический блок уже частично есть в FAQ — расширить в отдельную статью)
- Формат статей: четкая структура с подзаголовками H2/H3, буллеты, конкретные цифры и источники — это одновременно улучшает SEO-читаемость и GEO-цитируемость (AI-движки лучше извлекают факты из структурированного текста)

### 4.2 Кейсы → полноценные страницы
Превратить существующие короткие отзывы (Qazaq Petrol, Sunkar Pharm) в развернутые case-study страницы: задача клиента → внедрение → метрики до/после → цитата. Разметка `Review`.

## 6. GEO — оптимизация под AI-поисковики (ChatGPT, Perplexity, Google AI Overview, YandexGPT)

- [ ] Создать файл `llms.txt` в корне домена — краткое машиночитаемое описание компании, продукта, ключевых страниц
- [ ] Убедиться, что ключевые факты (цифры роста среднего чека, снижения затрат на ОКК, охват 100% диалогов) присутствуют в виде чётких, легко цитируемых формулировок в тексте страниц (не только в виде графики/цифр на скриншотах дашборда)
- [ ] Расширить блоки FAQ вопросами в разговорном стиле, максимально близком к тому, как пользователи формулируют запросы в AI-чатах («Как контролировать качество разговоров сотрудников на АЗС в Казахстане?»)
- [ ] Работа над присутствием в независимых источниках, которые индексируют AI-движки: отраслевые обзоры, каталоги SaaS-решений, публикации в казахстанских бизнес-медиа, YouTube (демо-видео уже есть на сайте — стоит вынести на YouTube с описанием)
- [ ] Убедиться, что контент доступен для краулеров без JavaScript-рендеринга (проверить, не блокирует ли текущая SPA-подобная структура парсинг текста ботами AI-движков)

## 7. Приоритизация (для разработчика)

1. **Сначала:** исправить NAP-несостыковку, создать robots.txt/sitemap.xml, проверить техническое SEO
2. **Затем:** архитектура — вынос отраслевых разделов на отдельные URL с внутренней перелинковкой
3. **Параллельно:** внедрение schema.org разметки (FAQPage, Review, Organization) — не требует смены архитектуры, можно делать сразу
4. **Далее:** контент — блог и кейсы (можно вести параллельно с разработкой, это не блокирует техническую часть)
5. **В последнюю очередь:** локальные карточки (2GIS, Google Business, Яндекс.Бизнес) и llms.txt — быстро делается после того, как NAP-данные зафиксированы
