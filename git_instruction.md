# 🚀 Шпаргалка по работе с Git (Git Flow)
> **Как правильно начинать день, вести разработку в ветках и отправлять код СТО без конфликтов.**

---

## 🌅 С чего начинать рабочий день (Или новую задачу)

Перед тем как написать хоть одну строчку кода, приведите локальный репозиторий в соответствие с сервером:

### Шаг 1. Перейдите в ветку `main`
```bash
git checkout main
```

### Шаг 2. Стяните все свежие изменения с сервера
*(Это загрузит коммиты, которые СТО принял или написал за то время, пока вы не работали)*
```bash
git pull origin main
```

### Шаг 3. Создайте новую ветку под вашу задачу
*(Название ветки пишите латиницей, через дефис, кратко описывая суть задачи)*
```bash
git checkout -b feature/название-вашей-задачи
```
*Примеры названий:* `feature/demo-light-theme`, `feature/okkm-title`, `bugfix/wave-animation`.

---

## 💻 Процесс работы (В течение дня)

Вы спокойно вносите изменения в код. Все изменения сохраняются только в вашей ветке. Когда локально всё проверено и готово:

### Шаг 4. Добавьте файлы и сделайте коммит
```bash
git add .
git commit -m "feat: краткое описание того что вы сделали на русском"
```

### Шаг 5. Отправьте (запушите) ветку на сервер
```bash
git push origin feature/название-вашей-задачи
```

### Шаг 6. Отправьте Pull Request СТО на проверку
После пуша зайдите в репозиторий на GitHub/Gitea, нажмите кнопку **Create Pull Request** и скиньте ссылку вашему СТО.

---

## 💡 Полезные команды на всякий случай

* `git status` — проверить, в какой вы ветке и какие файлы изменены.
* `git branch` — посмотреть список всех локальных веток (текущая будет подсвечена звездочкой).
* `git checkout main` — вернуться на главную ветку (всегда делайте это перед созданием новой ветки).
